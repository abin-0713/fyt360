> 面向：`xc.fishingbank.cn`（CentOS 7 + 宝塔 + PostgreSQL 16 + systemd 跑 fyt360-api）
> 前提：第一步的基础部署已经做过（`/root/fyt360-bt`、`/www/wwwroot/fyt360-src`、systemd 服务 `fyt360-api`）
> 本文只讲**把商城二开这套代码与数据上线**，含验证与回滚。

## 二、代码上线（二选一）

### 方式 A（推荐）：从你自己的 fork 升级

```bash
# 1) 本地把 shop 分支推到你的仓库（在开发机上做）
git remote add mine https://github.com/<你的账号>/fyt360.git
git push mine shop:main      # 或推成一个新分支，然后把下面 REPO_URL 指到它

# 2) 服务器上让升级脚本从你的仓库拉
cd /root/fyt360-bt
grep -q '^REPO_URL=' bt.env || echo 'REPO_URL=https://github.com/<你的账号>/fyt360.git' >> bt.env
DRY_RUN=1 bash upgrade.sh      # 先看它准备做什么
bash upgrade.sh                # 正式升级（自动重打本地补丁 + 重新构建 + 重启服务）
```

`upgrade.sh` 会：整仓备份到 `/root/backups/` → 拉上游（直连 + 3 个镜像回退）→ 硬重置 → 重跑
`deploy-bt.sh`（自动重打：安全补丁 / 本地图片存储 / API 域名 / 备案号）→ 迁移 → 构建 → 重启。

### 方式 A-2：用 git bundle（不依赖我的机器，离线可搬）

我这边已经把 `shop` 分支打成了 **git bundle**：`fyt360-shop.bundle`（9.6MB，含 7 个 commit 的完整历史）。
拿到这个文件后，你可以：

```bash
# ① 直接从 bundle 克隆出二开代码（不需要网络）
git clone fyt360-shop.bundle fyt360-shop -b shop

# ② 或者把它 fetch 进你已有的 fork 再推送（推荐，保留上游历史关系）
cd 你的fyt360仓库
git fetch /path/to/fyt360-shop.bundle shop:shop
git push origin shop          # 推到你的 GitHub，从此服务器可用 REPO_URL 从你的仓库升级
```

推送后回到方式 A 第 2 步（在服务器 `bt.env` 里加 `REPO_URL`，跑 `upgrade.sh`）。

### 方式 B：直接拷代码

```bash
# 开发机上打包 shop 分支（不含 node_modules）
git archive --format=tar.gz -o fyt360-shop.tgz shop
# 传到服务器 /root/，然后
cd /www/wwwroot && mv fyt360-src fyt360-src.bak-$(date +%s) && mkdir fyt360-src
tar xzf /root/fyt360-shop.tgz -C fyt360-src
cd /root/fyt360-bt && SKIP_INSTALL=0 bash deploy-bt.sh      # 会重新 npm ci + 迁移 + 构建 + 重启
```

## 三、数据上线

`deploy-bt.sh` / `upgrade.sh` 会自动跑：

```bash
node deploy/scripts/migrate.mjs     # 幂等重放全部迁移（含 100_shop_core.sql）
node deploy/scripts/seed.mjs        # 幂等
node deploy/scripts/migrate.mjs     # 全新库需要第二遍（上游 010 依赖 seed 的分类）
```

**上线前建议先看一遍迁移会做什么**（在开发机或服务器本地库上）：

```bash
npm run verify:shop          # 21 项：新表/扩列/存量回填/幂等
```

**回滚**：迁移只做新增列与新增表，不回滚也不会破坏上游功能；
真要回退代码，`cp -r /root/backups/fyt360-src-*.tgz` 解回来 + `systemctl restart fyt360-api` 即可。

## 四、新增定时任务（**必做，否则未支付订单的库存占用永不释放**）

宝塔 → 计划任务 → 新增「Shell 脚本」，每 5 分钟：

```bash
APP_DIR=/www/wwwroot/fyt360-src /root/fyt360-bt/jobs.sh shop-sweep
```

（`jobs.sh` 无需改动，任意任务名都支持；token 由 `HMAC(JWT_SECRET,'shop-sweep')` 现算。）

已有的 3 条继续保留：`ordersweep`(5min)、`ordersync`(30min)、`checkin-remind`(每日 09:00)。

## 五、前端构建与发布

```bash
cd /www/wwwroot/fyt360-src
export PATH=/www/server/nodejs/v22.23.3/bin:$PATH

# 后台（含商城 5 个页面）
npm run build:admin && cp -r apps/admin/dist/. /www/wwwroot/xc.fishingbank.cn/admin/

# H5（含商城 6 页；默认同源 API，无需配域名）
npm run build:h5 && cp -r apps/h5/dist/build/h5/. /www/wwwroot/xc.fishingbank.cn/h5/

# 小程序（必须指定自己的 API 域名）
VITE_API_BASE=https://xc.fishingbank.cn npm run build:mini
# → 产物 apps/mini/dist/build/mp-weixin，用微信开发者工具导入后上传
```

> 小程序还有两件平台侧的事：`manifest.json` 的 **AppID** 换成你的；
> 微信公众平台 → 开发设置 → **request 合法域名** 填 `https://xc.fishingbank.cn`。

## 六、上线后冒烟清单（5 分钟）

```bash
# 1) 服务与站点
curl -s https://xc.fishingbank.cn/healthz

# 2) 商城公开接口（应返回分类/商品）
curl -s "https://xc.fishingbank.cn/api/shop/goods?site=site-a" | head -c 200

# 3) 定时任务端点（token 由脚本现算，能跑通说明 JWT_SECRET 一致）
APP_DIR=/www/wwwroot/fyt360-src /root/fyt360-bt/jobs.sh shop-sweep
```

界面上走一遍（真机或后台）：

1. 后台 → 商城 → **商品分类** 建一个分类；
2. **运费模板** 建一个（按件：首件 6 元，续件 3 元）；
3. **商品管理** 新建商品（选分类/运费、加一个 SKU、填价格与库存）→ **保存并上架**；
4. 小程序/H5 打开商城 → 能搜到该商品 → 加购 → 结算（选地址）→ 下单；
5. 真机支付（**需先配微信支付商户号**；未配时后台/详情页可用"模拟支付"把流程跑通）；
6. 后台 → **商城订单** → 发货（填快递单号）→ C 端订单详情 **确认收货** → 应转"已完成"（同时触发返利结算）；
7. C 端 **申请售后** → 后台 → **售后审核** → 通过并退款 → 检查库存是否回补、冲销台账是否有记录。

## 七、已知边界（不是 bug，但要知道）

| 项 | 现状 | 怎么补 |
|---|---|---|
| H5 内拉起微信支付 | 未接公众号 JSSDK（浏览器里调不起收银台） | 用小程序下单支付；或后续接 JSSDK |
| 小程序支付 | **已接 `uni.requestPayment`**（条件编译，H5 自动剥离） | 配好商户号即可真机支付 |
| 微信退款 | 有商户号走 V3 退款；无商户号走 mock 通道自动落账 | 配 `site_payment` 即切换为真实退款 |
| 部分退款的佣金冲销 | **不自动**，台账标 `manual_review` | 运营人工处理（刻意设计：按比例改历史账会对不上） |
| 优惠券 | 商城券（`scope=self`）可选择；权益券（`scope=rights`）不走这里 | —— |
| 混类下单 | 实物/到店/虚拟**不能合并下单**（运费与履约语义不同） | 分开结算（接口明确 400） |
