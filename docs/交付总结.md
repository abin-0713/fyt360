## 六、顺手修掉的上游问题（5 个）

1. **H5 老用户进站必抛 JS 错误**：`apps/h5/src/core/bootstrap.js` 里 `const invite` 声明在使用之后 → 已登录用户命中 TDZ，首页配置拉取被中断。（用未改动的上游产物复现对照确认）
2. **后台菜单白名单硬编码**：`onSub` 的数组少了新菜单 → 侧栏能点但只弹"建设中"不切换页面。改为从 `menus` 派生。
3. **未开通站点的"纠偏"强行拉回凭据开通页**：只想开自营商城、不接 CPS 的站点永远进不去后台。改为仅在默认看板时提示。
4. **C 端订单详情不返回物流快照**：用户看不到快递单号。
5. **Element Plus 未挂语言包**：确认框 `OK/Cancel`、分页 `Total`、空表 `No Data`。挂上 `zh-cn`。

另有两处"钱的方向"的修正：最后一件退款**带上运费**（整单退完不该少退）；只传 `num` 不传 `item_id` 的歧义请求**显式 400**（原实现会静默按整单退）。

## 七、关键设计取舍（都是"宁可要人确认，也不静默算错"）

| 决策 | 原因 |
|---|---|
| 快递单补「确认收货」触发返利结算 | 上游返利在**核销**时发放，快递单没有核销动作 → 照搬会导致快递单佣金永远不发 |
| 部分退款**不自动**冲销佣金，台账标 `manual_review` | 多跳佣金按 level 各一行，按比例扣会污染历史账 |
| 结算失败不阻断确认收货 | 货已交付，返利是后台账务问题；失败留痕 + 后台可补结算 |
| 混类下单（实物/到店/虚拟）直接拒绝 | 运费与履约语义不同，合并只会让钱算不清 |
| 微信退款复用上游 V3 `refund()`；无商户号走 mock 通道 | 微信侧 `out_refund_no` 天然幂等；让没配商户号时也能跑通售后 |
| 迁移编号从 `100_` 起 | 永不与上游迁移冲突 |

## 十、运维要点

```bash
# 升级（服务器，务必带 BRANCH）
cd /root/fyt360-bt && DRY_RUN=1 bash upgrade.sh && bash upgrade.sh
#   bt.env 必须有两行：REPO_URL=https://github.com/abin-0713/fyt360.git  /  BRANCH=shop
#   ⛔ 不写 BRANCH 会 reset 到 main（等于上游）→ 商城代码被冲掉

# 本地验收（开发机）
npm run verify:shop / :shop-chain / :shop-admin / :shop-refund
PLAYWRIGHT_BROWSERS_PATH=$PWD/.pw-browsers npm run verify:shop-h5 / :shop-admin-ui

# 定时任务（独立文件，不碰宝塔计划任务）
cat /etc/cron.d/fyt360-shop        # */5 * * * * ... jobs.sh shop-sweep
APP_DIR=/www/wwwroot/fyt360-src /root/fyt360-bt/jobs.sh shop-sweep   # 手动触发

# 备份与回滚
ls /root/backups/                  # 数据库 dump / 代码包 / 前端产物包
# 回滚：rm -rf /www/wwwroot/fyt360-src && tar xzf <备份> -C /www/wwwroot && systemctl restart fyt360-api
```
